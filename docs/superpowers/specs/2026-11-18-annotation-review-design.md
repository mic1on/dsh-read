# 批注回看、问答展开与原文定位

日期：2026-11-18  
任务：DSH-3  
状态：用户已确认；阅读器内批注面板与保守定位已实现，使用说明见中英文 README。

2026-11-19，按 DSH-6 反馈补充集成规则：搜索预览与批注面板互斥，搜索期间禁用批注入口及正文标记，
先返回原位置或确认继续后才能回看批注。两者共用导航失效序号，旧请求不能覆盖新窗口；正文版本变化
使旧上下文失效。搜索游标绑定路径、正文版本与查询，避免批注 fresh 读取或解包 EPUB 重新解析误使续页失效。

## 目标与现状

补齐当前书籍的“批注列表 → 摘录／笔记／已保存问答 → 返回原文”闭环。
现有 `GET /dsh-read/api/notes?path=…` 已返回完整批注数据；`NotesStore` 的 JSON
继续作为事实源，Markdown 继续作为可选镜像。此次不改变批注、问答或阅读进度的存储格式。

改动前正文标记只提示数量；书籍 LRU 缓存不检查磁盘变化。因此原文定位不能直接调用旧段落跳转，
也不能只依赖客户端已缓存的正文。

## 备选交互与建议

1. **推荐：阅读器内的批注面板。** 工具栏新增“批注”，在卡片正文区域切换批注面板；
   正文标记打开同一个面板并筛选当前段落。直接复用阅读器上下文，窄窗口也能使用。
2. **正文下逐段内嵌展开。** 原文与批注距离近，但长回答会挤占正文，整本书仍需另外做列表入口。
3. **设置页独立批注中心。** 适合跨书管理，但当前任务只浏览当前书籍，且来回切换阅读上下文更繁琐。

建议采用第一项；不增加跨书管理、编辑、删除、全文搜索或新的模型请求。

## 推荐面板行为

- “批注”按钮打开当前书籍的全部批注，按段落号、创建时间排列。每条可展开查看完整内容。
- 正文批注标记有明确的按钮标签，点击后显示该段落的全部批注并展开；面板提供“全部批注”和“返回阅读”。
- 面板与正文共用卡片的可用内容区并分别滚动，避免长回答撑高会话或使控制区不可达。
- 打开面板时暂停播放，保留当前段落和逐字光标；返回阅读后保持暂停，由用户按播放继续。
  仅浏览／刷新批注不修改续读位置。
- 面板打开及“刷新”重新查询；不轮询。保存批注和现有的阅读器重新聚焦刷新继续生效。
- 按书路径请求并在书籍／会话变化时清理面板状态；旧请求不能把前一本书的数据写入新上下文。

## 内容与异常状态

- 展示段落号、类型、创建时间、引用原文；个人笔记显示已保存的 `text`，为空时显示“未填写笔记”。
- 问答显示实际已提交的 `question`，旧记录回退到已保存文本；没有问题内容时说明尚未保存问题。
- `answered` 且正文非空：显示“已保存回答”和完整已保存正文。
- `pending`：显示“回答尚未完成或尚未归档”；已有部分正文仍可阅读，不承诺实时回填。
- `interrupted`：显示“回答未完成”，保留部分正文；截断记录额外标记“回答已截断”。
- 历史记录缺少状态、状态不识别，或标记已回答却没有正文：显示“回答不可用”，不冒充完整问答。
- 摘录、笔记、问题、回答均作为纯文本显示并保留换行，不注入 HTML。
- 显示“正在加载…”、当前书籍空列表、当前段落无批注、加载失败和“重试”。刷新失败时可保留
  当前已显示的旧记录，但明确说明未刷新成功。
- 展示的是插件 JSON 已保存内容；Obsidian 中额外手写的内容不在此次同步范围。

## 定位策略与建议

**推荐采用保守校验，不自动迁移段落。** 点击一条批注的“定位原文”时，由 Host 按书路径和批注 ID
重新读取已保存记录与磁盘原书，绕过旧解析缓存。仅在下列条件同时成立时定位：

1. 书籍存在且能正常解析，批注属于请求的书籍。
2. 批注具有有效的原段落号和非空摘录。
3. 摘录与当前原段落匹配；只统一空白字符，不做模糊匹配或忽略标点。
4. 同一摘录只在当前书籍的一个段落中出现，能够排除重复引用的歧义。

成功时返回本次解析的书籍元数据和目标附近正文，客户端一次性替换正文窗口，完整展示目标段落，
高亮并滚动到该段落，关闭面板并保持暂停。不能先改变光标再等待正文请求成功。
定位成功按现有手动跳段逻辑更新续读位置；失败不改变原来的段落、光标和进度。

文件缺失、解析失败、批注已删除、引用为空、段落越界、摘录不匹配或重复出现时，留在面板，
展示具体原因并允许重试。前文插入导致段落位移时也停止定位，提示内容可能已变化；不猜测新位置。

可选替代策略是“原段落不匹配时，在全书查找唯一精确摘录并定位新段落”，对插入前文更友好，
但会自动改变批注对应位置。建议首版先采用保守策略。

为避免定位后再次读到旧解析结果，定位使用的最新书籍解析应替换 Host 的缓存；后续分页应检查
源文件是否发生变化。解包 EPUB 的正文文件变化同样需要被识别，不能只检查顶层目录时间。

## 实现边界

- 复用 `/notes` 读取和现有存储／归档写入逻辑；不修改归档捕获状态机。
- 新增按路径及批注 ID 定位的 Host 操作；Host 返回可直接显示的已校验窗口，沿用已有书籍格式白名单。
- 列表／展开与定位状态和普通阅读加载状态分开，互不吞掉错误。
- 定位进行中避免重复请求；卸载、切书／切会话、更新阅读进度和新的导航动作使旧定位响应失效。
- 不新增运行时依赖，不引入构建步骤。
