# 书内搜索性能与验证记录

测量日期：2026-11-18。测试书为脚本生成的 11,090,679 字节（10.58 MiB）中英混合文本，
含 50,000 段正文、50 个章节标题，共 50,050 段；解析后正文长 4,890,079 个 UTF-16 单元。
生成器及断言位于 `scripts/benchmark-search.mjs`，不依赖私人书籍或模型。

## Host 检索

环境：macOS / arm64 / Apple M5 / Node v22.23.2。每个场景先预热，再测 20 次；
P95 为排序后第 19 个样本。首次磁盘读取及解析为 46.053 ms，不计入缓存检索。
每次请求最多返回 20 条，测量不包括 HTTP 往返及前端防抖。最终版本在双版本完整回归并行运行时
复测如下，首次解析为 46.310 ms；以下使用最终复测数值。

| 场景 | 页 | 返回数 | P95（ms） | 最大（ms） |
| --- | --- | ---: | ---: | ---: |
| 密集命中「原文」 | 首页 | 20 | 0.069 | 0.108 |
| 密集命中「原文」 | 续页 | 20 | 0.026 | 0.069 |
| 稀疏命中「LIGHTHOUSE」，每千段一处 | 首页 | 20 | 2.765 | 2.779 |
| 稀疏命中「LIGHTHOUSE」 | 续页 | 20 | 1.606 | 1.820 |
| 无命中，扫描整本 | 首页 | 0 | 6.951 | 7.916 |

各场景均满足已确认的 P95 ≤ 500 ms。Node v26.7.0 额外测量的最慢场景 P95 为 4.794 ms，
首次解析 32.997 ms。重跑命令（可选第二参数保存 JSON）：

```bash
node scripts/benchmark-search.mjs .tmp/search-performance.json
```

## 浏览器响应及交互

环境：Ego Lite Chromium 156、React 18.3.1 production，同一台 Apple M5。
使用临时 loopback 测试页挂载仓库原始 `lib/client.js`，连接原始 `index.mjs` 注册的搜索及段落路由，
加载同样的长书。进度由独立的测试存储记录，未接入用户书库或当前 DSH 会话。
该结果验证插件的真实 React 渲染与 HTTP 路由，未代表完整 DSH 外壳的生产安装验证。

| 指标 | 样本 | P95（ms） | 最大（ms） | 阈值 |
| --- | ---: | ---: | ---: | --- |
| 搜索 onChange 处理函数（取消旧请求、更新状态） | 20 | 0.100 | 0.200 | ≤ 100 ms |
| JSON 读取完成至结果 DOM 提交后的下一帧 | 21 | 5.100 | 6.600 | ≤ 100 ms |

交替输入中文密集词和英文稀疏词共 20 次，加一次续页。250 ms 输入防抖不计入以上两项，
Host 扫描及网络请求也不计入渲染指标；此指标包括 React 更新、DOM 提交及下一帧等待，
不等同于完整页面的 INP。每页只有 20 个结果节点，翻页替换旧页，无浏览器脚本错误。

实际浏览器还验证了：

- 搜索第 2 页可跳至零基段落 21,020，正确加载窗口并高亮目标文字。
- 输入、翻页、预览及返回期间测试进度存储为空。
- 阅读至第 11 段并暂停后，搜索/预览再返回，段落索引和已显示字符完全一致。
- 点击「从此处继续阅读」后才出现目标段落（零基 1,000）的进度写入。
- 截图检查了卡片内结果滚动区、章节及段落标签、正文高亮；高亮使用主题前景和浅色混合背景。

## 回归与边界

最终 Node v22.23.2 和 v26.7.0 各 230 项测试全通过，新增 29 项。
8 个变更 JavaScript 文件通过 Node 22 语法检查，`git diff --check` 通过。

`test/book-search.test.mjs` 验证有界分页、同段多命中、分块边界、长段落、输入/游标校验、
图片跳过及事件循环取消；`test/book.test.mjs`、`test/host.test.mjs` 验证所有既有可解析格式
（含 MOBI/AZW/AZW3、打包/解包 EPUB、所有文本扩展名）、HTTP 错误及搜索不改进度。
`test/client.test.mjs` 覆盖防抖、乱序、分页、失败重试、HTML 文本安全、精确返回、确认继续、
卸载/切书/切会话、预览后重新挂载和阅读中心进度覆盖。

这是合成纯文本长书的本机测量，其他设备、格式首次解析和压缩比例会影响耗时。
仍沿用原有 3 本解析 LRU 及源文件缓存有效期；搜索游标绑定当前解析实例和查询。
如缓存被逐出、宿主重启或重新解析，旧游标明确报错，需要重新搜索，不会悄悄接续到另一本或另一版正文。
首次解析由现有解析器执行，扫描过程才按 32 KiB 分块让出事件循环；不建立全文索引或长期查询缓存。
